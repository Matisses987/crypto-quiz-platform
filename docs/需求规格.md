## 1. 范围

### 1.1 本平台必须实现

1. **F1 自动分类**：按题库三级结构（部分 → 章 → 题型）+ 知识点标签自动归类（标签由确定性规则从题干/选项抽取，词表见 5.6）。
2. **F2 练习出题与自动批改计分**：① 分类练习（三级结构 + 标签筛选）；② 全库随机练习；两种模式均随机出题、逐题即时自动批改、本轮计分。
3. **F3 错题本**：自动进出 + 手动移出 + 错题重练。
4. **F4 信心三色标记**：提交后立即选择「有把握 / 带猜测」，三色规则按 D6。
5. **F5 学习统计**：每题对/错次数 + 每题掌握指数 + 全局掌握指数（样本不足按 D7）。
6. **F6 按日导出 + 导入汇总**：按本地自然日（或日期区间、或全部）导出学习情况 JSON；导入后统计团队易错题、个人易错题与成员对比，重复导入不重复计数。
7. **E1 模拟选拔赛**：100 题不重复、60 分钟、100 分、到点自动交卷，交卷后按 填空→多选→单选→判断 输出分项得分与用时（对齐官方同分排名规则）。
8. **X1 手动纠错覆盖层**：题目「标疑问」、手动改答案（支持多答案）、覆盖层随导出共享、导入后生效。

### 1.2 明确不做（非目标）

- 不纳入实操题 12 道（D12）；不提供实操题界面、数据、链接。
- 不做联网、账号、服务器、云同步；不做跨设备实时同步（只靠 JSON 导出/导入）。
- 不做移动端适配（电脑端为主，最小可用宽度 1024px；窄屏可横向滚动即可）。
- 不做题目解析正文录入（题库无解析内容，不生成、不编造解析）。
- 不做自动 OCR / 自动抓取题库；题库在构建期一次性解析并内嵌。
- 不修改任何既有输入文件（报名资料、赛事通知、题库 PDF、照片等）：所有产物只写在新建目录内。

### 1.3 交付物布局

```

├─ docs/需求规格.md          ← 本文件
├─ tools/                    ← 题库解析与内嵌构建脚本（Node，构建期使用）
├─ src/                      ← 源码（HTML 模板 / 样式 / 逻辑 / 题库 JSON）
└─ dist/密码赛刷题平台.html   ← 成品：唯一交付文件，双击可用
```

## 2. 术语与数据流总览

| 术语 | 含义 |
| --- | --- |
| 题库对象 question | 内嵌在 HTML 中的一道理论题（含答案），字段见 5.1 |
| 作答记录 record | 一次「本题提交」的完整事实记录，字段见 6.2 |
| 错题本 wrongbook | 由作答记录驱动的题目状态集合，规则见 8.3 |
| 覆盖层 overrides | 用户手动修正（改答案/标疑问）的持久化层，字段见 6.4 |
| 模拟赛 paper/session | 一次 100 题、60 分钟、100 分的模拟卷及其结果，字段见 6.5 |
| 导出文件 payload | 含昵称的学习记录 JSON 文件，字段见 7.2 |
| 团队 team | 本地昵称 + 所有已导入文件中的不同昵称的集合，成员即「昵称」 |
| responseMode 作答方式 | 决定渲染哪种作答控件与判分方式（`single`/`multiple`/`judge`/`blank`），由 `sectionType` 与答案长度推导（见 5.3.3），与题库结构分类（`sectionType`）解耦 |
| 物理序 seq | 题目在「某章某题型」区块中的第几道（第 1 道=1），与打印题号可能不同（见 5.3 缺陷 A） |

**数据流**：

```
题库 PDF（构建期，只读；见 `docs/题库来源.md`）
  └─tools/ 解析 → src/bank.json → 内嵌进 dist/密码赛刷题平台.html（<script id="bank-data" type="application/json">）
运行时：
  内嵌题库 + localStorage 覆盖层 → 生效题库（effective bank，见 9.10）
  user 作答 → 判分(CQP.judge) → 颜色(CQP.color) → 写作答记录 → 更新错题本(CQP.wrongbookApply) → 更新统计(掌握指数)
  导出(CQP.exportPayload) → JSON 文件（含昵称）
  导入(CQP.validateImport → CQP.mergeImport) → 合并去重 → 团队/个人易错题统计(CQP.teamStats / CQP.personalStats)
```

## 4. 运行环境与约束

| 项 | 约定 |
| --- | --- |
| 运行形态 | 单文件 HTML，`file://` 协议双击打开；无需服务器、无网络 |
| 浏览器 | Windows 电脑端 Chrome / Edge 最新稳定版（主测）；Firefox 可用为佳 |
| 存储 | 仅 `window.localStorage`；键前缀 `cqp.v1.`；不使用 IndexedDB / Cookie / SessionStorage / Service Worker |
| 存储写入失败（配额/隐私模式） | 弹出阻断式提示「本地存储不可用，请立即导出备份」，仍允许本次会话继续使用内存态（刷新即丢失） |
| 导出 | `Blob` + `<a download>`；不调用任何网络接口 |
| 导入 | `<input type="file" accept=".json,application/json">` + `FileReader.readAsText` |
| 性能 | 内嵌题库 ≈ 1051 题，首次渲染与筛选响应 < 300ms（Chrome 桌面，i5 级） |
| 可测试性 | 全部纯函数挂到 `window.CQP`，测试脚本可直接调用（见第 9 章）；测试钩子 `window.CQP.__test` 暴露 `bank`、`makeRecord` 等 |
| 代码风格 | 单文件内 `<style>` + `<script>`；JS 为 ES2020，不使用模块导入（保持 `file://` 可运行） |

#### 5.3.1 id 规则（冻结）

`id = "Q-" + chapterCode + "-" + typeCode + "-" + seq(4 位补零)`

| 题型 | `typeCode` |
| --- | --- |
| 单选题 | `S` |
| 多选题 | `M` |
| 判断题 | `J` |
| 填空题 | `F` |

- 示例：`Q-C01-S-0002`、`Q-C04-M-0009`、`Q-C05-F-0001`、`Q-C07-J-0030`。
- `seq` 取**物理序**（文档顺序），因此不受打印题号缺陷影响：C05 单选物理序 60 = 未编号题（`printedNo=null`），其后打印题号 60 的题物理序为 61。
- id 一经发布不得变更（作答记录、错题本、覆盖层均以其为外键）。题库重建若改动章节、题序，必须递增 `bankVersion`，且导入时对未知 id 的记录归入 `report.unknownQids`（不参与统计但保留原始数据）。

#### 5.3.3 `responseMode` 推导规则（冻结）

```
responseMode(question) =
  sectionType = "judge"    → "judge"
  sectionType = "blank"    → "blank"
  sectionType ∈ {single, multiple} 且 answer.length ≥ 2 → "multiple"
  sectionType ∈ {single, multiple} 且 answer.length = 1 → "single"
```

- 影响范围（本库实测）：`Q-C06-S-0004`、`Q-C07-S-0027` 的 `responseMode="multiple"`（渲染复选框）；`Q-C04-M-0002`、`Q-C04-M-0009`、`Q-C06-M-0008` 的 `responseMode="single"`（渲染单选按钮）；其余题目 `responseMode === sectionType`。
- **结构分类（F1）与统计分组一律用 `sectionType`；作答控件与判分一律用 `responseMode`。**两者不得混用。
- `sectionType` 与 `responseMode` 不一致的题目必须写入 `src/bank.build-report.json` 的 `buildWarnings[]`（要素：`id`、`sectionType`、`responseMode`、`answer`）。

#### 5.3.4 行内空白口径（v1.1.2 补充，非判据变更）

**口径（冻结）**：题库题干与选项**允许保留**源自 PDF 文本层的**行内空白**。构建期的空白处理只有两步，顺序固定：

1. **同一行内**：连续空白（半角空格 / 制表符 / 全角空格 `U+3000`）压缩为 **1 个半角空格**，并裁剪该行首尾空白（实现即 `norm_ws(s) = re.sub(r"\s+", " ", s).strip()`）；
2. **跨行合并**（§5.3 既有判据，**逐字不变**）：相邻均为中日韩字符时**直接拼接、不加空格**；否则拼接处加 **1 个半角空格**。

即：**不删除行内单个空格**（包括两个汉字之间的单个空格），也不做同义替换、不重排语序、不改标点、不做全角→半角宽度转换（宽度折算只发生在填空**判分**时，见 §9.3）。

**现状量化（评审与本规格独立复算完全一致）**

- 规则：把「题干 + 全部 `options[].text`」拼接后匹配 `[\u4e00-\u9fff] [\u4e00-\u9fff]`（汉字 + 单个半角空格 + 汉字）。
- 结果：**81 题 / 133 处**（占 1051 题的 7.7%）；较明显的 4 题：`Q-C05-M-0120` 14 处、`Q-C05-S-0095` 12 处、`Q-C05-M-0117` 11 处、`Q-C05-S-0134` 7 处。
- 来源：全部**在 PDF 文本层中原样存在**，非解析器添加。多数是标准/术语命名的合法分隔（如「信息技术 安全技术 密钥管理 第 3 部分」），少量是排版噪声（如 `Q-C05-S-0095` 的「SSL 协 议 的 密 码 套 件 中」）。
- 产物中**不存在**连续双空格，也**不存在** `U+3000`（实测 0 题）——第 1 步的压缩与裁剪已生效。

**为何不影响交付口径（逐项核对）**

| 面 | 结论 | 依据 |
| --- | --- | --- |
| 判分 | 不受影响 | 选择题按字母比较（`exact` / `set_equal`），**不比对题干或选项文本**；填空题按 §9.3 对「用户输入 × 标准答案」两侧归一（折叠 → `trim` → 小写），题干空白不参与；判断题只比对 `对`/`错` |
| 题目 id | 不受影响 | `id` 由 `chapterCode + typeCode + seq` 生成（§5.3.1），与文本无关 |
| 导出 / 导入 | 不受影响 | 导出文件只含作答记录、覆盖层与模拟赛（§7.2），**不存题干/选项**；去重键为 `nickname + qid + ts`（§7.6） |
| 统计 / 掌握指数 | 不受影响 | 统计只读 `records`（`qid`、对错、信心、用时），与文本无关（§8.4–§8.6） |
| 知识点标签 | 可能轻微影响命中率，但已达标 | 若关键词被空格拆开则该条规则不命中，回落为章级兜底（§5.6）——属词表设计范围（早期观察 O-4，处置见 §16.6：延后到交付之后）；最终具体标签命中率 **83.73%（880/1051）≥ 80%** 门禁 |
| 难度 | 不受影响 | 按章节/题型结构规则推导（§5.7），不读文本 |
| 展示 | 允许应用层处理 | 渲染可用 CSS 处理空白；也可在「校对/纠错」面板提示或标疑问，但**不得回写修改题库文本**（保持与 PDF 文本层逐字一致） |

**边界声明**：本小节仅补充空白口径，**不改变 §5.3 的任何既有判据**——字段名/类型/枚举、断行合并规则、`printedNo`/`needsReview`/`answerStatus` 语义均逐字未变；`stem` 与 `options[].text` 的字段语义仍为「与 PDF 文本层一致的纯文本」。

### 5.4 答案规范（冻结）

| 题型 | `answer` 规范 | 原文示例 | 规范后 |
| --- | --- | --- | --- |
| 单选 | 单元素数组，元素为大写字母 | `答案：C` | `["C"]` |
| 多选 | 多元素数组，元素为大写字母，**升序排列且去重** | `答案：ABD`、`答案：ABCD` | `["A","B","D"]` |
| 判断 | 单元素数组，元素为 `"对"` 或 `"错"`（中文，非 T/F） | `答案：对` / `答案：错` | `["对"]` / `["错"]` |
| 填空 | 1～n 个可接受答案，元素为**原文串**（去首尾空白，保留内部空格与大小写） | `答案：SM4` | `["SM4"]` |

- 多选答案必须升序：实测全库 358 道多选答案均为升序无重复（如 `AB`、`ABC`、`ABCD`），构建脚本对非升序答案必须重新排序并写入 `buildWarnings`（不得静默改变语义）。
- 判断题不接受 `T/F`、`√/×`、`true/false`；若原文出现（实测 0 例），构建脚本报错退出。
- 填空题「多答案」写法：`answer` 数组多元素即多答案（例如未来题库为 `["SM4","SM4算法"]`）；本库 30 道填空均为单答案，多答案能力由 X1 覆盖层补录使用（D4）。
- **填空答案的全角/半角口径（r2 决定）**：`answer` 数组内始终保存**印刷原文**（例如 `["SM4"]`、`["256"]`），**不在数据层做全角折叠**；折叠只发生在判分比较时（§8.1 / §9.3），因此改开关不需要重建题库。
- **人工补录答案（r2）**：`Q-C05-F-0007` 的 `answer=["16"]` 属人工补录，`rawAnswer=null`（原文无答案行）、`needsReview=true`、`reviewReason="answer_missing"`；补录值以固定值注入构建结果，不由解析器推断，保证重建可重复（见 §16）。
- 填空题原文空位形态实测：下划线式（`____`、`______`、`_ _`、`___`）32 处、隐式空位（`为 。`、`是 。`、` 比特。`）5 处；解析后**保留空位标记原样**（不替换、不删除），`blankCount` 用于渲染，见 11.2.4。

### 5.5 章节与题型的渲染顺序（冻结）

1. 部分：基础题（B）→ 专业题（P）。
2. 章：C01、C02、C03、C04、C05、C06、C07。
3. 题型：单选题 → 多选题 → 判断题 → 填空题。

### 6.1 `cqp.v1.meta`

```json
{
  "schemaVersion": "1.0.0",
  "appVersion": "1.0.0",
  "nickname": "小明",
  "deviceId": "d-7f3a91c2",
  "createdAt": "2026-09-16T21:00:00+08:00",

}
```

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `schemaVersion` | string | 固定 `"1.0.0"`；主版本不同 → 见 6.6 |
| `appVersion` | string | 应用版本，形如 `1.0.0` |
| `nickname` | string | 1～20 字符，非空白；用于导出与统计归属；首次进入时必填（弹窗），可随时修改；修改昵称**不**改写历史记录的 `nickname` 字段（历史记录归属不变） |
| `deviceId` | string | 形如 `d-` + 8 位小写 hex；首次生成（`crypto.getRandomValues` 或 `Math.random` 兜底），仅用于展示与审计 |
| `createdAt` / `updatedAt` | string | ISO-8601 含时区，格式 `YYYY-MM-DDTHH:mm:ss+08:00` |

### 6.2 `cqp.v1.records`：作答记录 `AttemptRecord[]`

```json
{
  "recordKey": "小明\u0001Q-C01-S-0002\u00012026-10-05T21:14:03+08:00",
  "qid": "Q-C01-S-0002",
  "nickname": "小明",
  "ts": "2026-10-05T21:14:03+08:00",
  "localDate": "2026-10-05",
  "mode": "practice_chapter",
  "sessionId": null,
  "myAnswer": ["B"],
  "correct": true,
  "confidence": "confident",
  "color": "green",
  "elapsedMs": 12400,
  "bankVersion": "2026.08-pdf1",
  "appVersion": "1.0.0"
}
```

| 字段 | 类型 | 必填 | 取值/约束 |
| --- | --- | --- | --- |
| `recordKey` | string | 是 | 去重主键：`nickname + "\u0001" + qid + "\u0001" + ts`；写入前由 `CQP.recordKey()` 生成；同一 key 视为同一事实 |
| `qid` | string | 是 | 题目 id（5.3.1） |
| `nickname` | string | 是 | 作答时的昵称（1～20 字符） |
| `ts` | string | 是 | 提交时刻，ISO-8601 含**本机当前时区偏移**，秒级精度、**不带毫秒**，格式 `YYYY-MM-DDTHH:mm:ss±HH:mm`；时区口径 = 作答时的系统本地时区；跨时区使用不做换算（如实记录偏移） |
| `localDate` | string | 是 | `YYYY-MM-DD`，= `ts` 在**其自身时区偏移**下的自然日；写入时由 `CQP.localDateOf(ts)` 计算并固化（后续筛选只读该字段，避免时区漂移） |
| `mode` | string | 是 | 枚举：`"practice_chapter"`（分类练习）、`"practice_random"`（全库随机）、`"wrongbook"`（错题重练）、`"mock"`（模拟赛） |
| `sessionId` | string \| null | 是 | `mode="mock"` 时为模拟赛 id（6.5）；其余为 `null` |
| `myAnswer` | string[] | 是 | 单选：`["B"]`；多选：升序去重字母数组如 `["A","C"]`；判断：`["对"]`/`["错"]`；填空：`["sm4"]`（用户原始输入，单元素，未做归一化）；跳过不记录（不产生本条记录） |
| `correct` | boolean | 是 | 判分结果，由 `CQP.judge()` 产生（9.3） |
| `confidence` | string | 是 | 枚举 `"confident"`（有把握）、`"guessed"`（带猜测）；未点选时默认 `"confident"`（D5） |
| `color` | string | 是 | 枚举 `"green"`（有把握且对）、`"yellow"`（猜对）、`"red"`（错）；由 `CQP.color()` 产生，冗余存储便于统计与导出核验 |
| `elapsedMs` | integer | 是 | ≥0，本题从展示到提交的毫秒数；超过 86 400 000（24 小时）按 86 400 000 截断存储 |
| `bankVersion` | string | 是 | 作答时题库版本 |
| `appVersion` | string | 是 | 作答时应用版本 |

**存储形态**：`localStorage["cqp.v1.records"]` = 上述对象的 JSON 数组，按 `ts` 升序追加。单条记录典型体积 ≈ 320 字节；10 万条 ≈ 32MB，超出配额时按 4. 的失败策略处理。

**颜色与记录的对应关系（冻结）**：

| 判定 | `correct` | `confidence` | `color` |
| --- | --- | --- | --- |
| 有把握且对 | true | confident | green |
| 猜对 | true | guessed | yellow |

### 7.3 导出范围筛选规则（冻结）

| `scope` | 记录筛选条件 | `mockSessions` 筛选条件 | 导出按钮文案 |
| --- | --- | --- | --- |
| `day` | `localDate === 指定日` | `submittedAt` 的本地日 = 指定日 | 「导出这一天」 |
| `range` | `from ≤ localDate ≤ to`（闭区间） | `from ≤ 本地日(submittedAt) ≤ to` | 「导出区间」 |
| `all` | 全部记录 | 全部 | 「导出全部」 |

- 日期选择器为 `<input type="date">`，默认值 = 今天（本地自然日）。
- `from > to` → 前端禁止导出并提示「起始日期不能晚于结束日期」。
- 导出内容与界面当前筛选（章/标签）无关；导出是「按日期的学习情况」的唯一语义（REQ-F6-01）。

### 7.4 覆盖层导出规则（冻结）

- 覆盖层**整体导出**，不按日期裁剪（否则会造成「改答案丢失」）；`counts.overrides` = `Object.keys(overrides.items).length`。
- 导入时覆盖层按 qid 合并，冲突规则见 7.6。

### 7.5 导入校验规则（冻结，`CQP.validateImport`）

按顺序执行，**任一硬错误即整体拒绝**（不产生部分合并）：

| 顺序 | 校验 | 失败码 | 结果 |
| --- | --- | --- | --- |
| 1 | 文本可 `JSON.parse` | `E_PARSE` | 拒绝，提示「文件不是合法 JSON」 |
| 2 | `kind === "cqp-export"` | `E_KIND` | 拒绝，提示「不是本平台的导出文件」 |
| 3 | `schemaVersion` 主版本 = `1` | `E_VERSION` | 拒绝，提示版本不兼容 |
| 4 | 必填字段与类型齐备（7.2 表） | `E_SCHEMA` | 拒绝，其余提示缺失字段路径 |
| 5 | `counts` 与实际数组长度一致 | `E_COUNTS` | 拒绝，提示「文件已损坏（计数不一致）」 |

软错误（**跳过并报告，不阻断**）：

| 顺序 | 校验 | 处理 |
| --- | --- | --- |
| 6 | 每条记录：`qid` 匹配 `^Q-C\d{2}-[SMJF]-\d{4}$`、`ts` 匹配 ISO 正则、`myAnswer` 为字符串数组、`confidence ∈ {confident,guessed}`、`correct` 为 boolean | 不合法记录 → 跳过，计入 `report.skipped[]`（附原因与原始片段） |
| 7 | 记录的 `localDate` 与 `localDateOf(ts)` 不一致 | 以 `localDateOf(ts)` 重算覆盖，计入 `report.repaired[]` |
| 8 | `qid` 未出现在当前题库 | 保留原始记录到 `report.unknownQids[]`，**不写入 records**（不参与统计） |
| 9 | `qid` 的 `bankVersion` 与当前不同 | 允许导入，计入 `report.versionMismatch[]` |

### 7.6 去重与合并规则（冻结，`CQP.mergeImport`）

1. **记录去重键**：`recordKey = nickname + "\u0001" + qid + "\u0001" + ts`（与 6.2 一致）。
2. 文件内重复（同文件出现两个相同 `recordKey`）→ 保留第一个，第二个计入 `report.duplicatesInFile`。
3. 与本地已有记录重复 → 跳过，计入 `report.duplicates`。
4. 合并为**只增不改**：本地已有记录永不被导入记录覆盖（即使时间更晚）。
5. 统计口径：作答次数、正确率、团队易错题计数一律基于去重后的记录集合，因此「同一文件重复导入 N 次」与「导入 1 次」结果完全一致（REQ-F6-02 的核心断言）。
6. **覆盖层合并**：按 qid 比较 `updatedAt`，取较新者；`updatedAt` 完全相同时，`updatedBy` 字典序较大者胜出（作为确定性 tie-break）；合并后写入本地 `cqp.v1.overrides`；`report.overridesApplied`（新增或更新）、`report.overridesKept`（本地更新，保留本地）。
7. **模拟赛合并**：按 `sessionId` 去重；已存在则不覆盖。
8. `report` 结构（冻结）：

```json
  "duplicatesInFile": 0,

  "unknownQids": [],

  "overridesApplied": 3,

  "sessionsImported": 1,

}
```

## 8. 统计、判分与状态规则（冻结口径）

### 8.1 判分口径总表

| `responseMode` | 用户作答 | 判定 | 说明/边界 |
| --- | --- | --- | --- |
| `single` | 单选按钮，得到 1 个字母 | `answer.length === 1 && myAnswer[0] === answer[0]` | 大小写敏感（字母为大写 A–D）；未作答（`myAnswer=[]`）判错 |
| `multiple` | 复选框，得到 0～4 个字母 | 集合相等：`sort(myAnswer) === sort(answer)` | **全对才算对**（D3）：漏选、多选、少选一律判错；字母升序存储 |
| `judge` | 「对 / 错」两个按钮 | `myAnswer[0] === answer[0]`，答案为 `"对"`/`"错"` | 不接受 T/F、√/× |
| `blank` | 文本框，得到 1 个字符串 | 先对**用户输入与每个标准答案两侧同时**做全角→半角折叠，再 `trim + toLowerCase`，然后任一命中即对：`fold(myAnswer).trim().toLowerCase() === fold(a).trim().toLowerCase()`，`a ∈ answer`；`fold(s)` = 逐字符 `U+FF01–U+FF5E → U+0021–U+007E`（即 `code - 0xFEE0`），`U+3000 → U+0020`，其余字符原样 | 忽略**首尾空格**与**大小写**（D4）；r2 起额外折叠**全角/半角**（0.3 R2-1）；**不删除内部空格、不做同义替换、不设数值容差**（`"SM 4"` ≠ `"SM4"`、`"128"` ≠ `"128.0"`）；折叠由 `CQP.DEFAULTS.blankFoldWidth` 控制，默认 `true`（关闭时仅 `trim + toLowerCase`）；`answer=[]` 时该题不作可判分题（防御分支，当前题库 0 例，见 13.1） |

- 判分返回结构化结果：`{correct, normalizedAnswer, normalizedResponse, reason}`，`reason ∈ {"exact","set_equal","string_match","no_answer","invalid_response"}`（9.3）。
- `sectionType` 不参与判分；一律以 `responseMode` 决定控件与判定。

### 8.2 计分（练习与模拟赛）

| 场景 | 得分规则 | 展示 |
| --- | --- | --- |
| 分类练习 / 全库随机 / 错题重练 | 每题 1 分，`score = 本轮答对题数`，`maxScore = 本轮题数`（跳过题不减少 `maxScore`，但记为未答） | 「正确 12 / 共 20（正确率 60.0%）」；正确率保留 1 位小数 |
| 模拟选拔赛 | `score = 答对题数 × 1`，满分 100 | 「76 / 100」+ 分项表（10.4） |

### 8.3 错题本进出规则（冻结，`CQP.wrongbookApply`）

**进入条件**（任一满足即进入，`state` 置 `active`，`addedAt` 更新为本次时间，`confidentStreak` 置 0）：

1. `correct === false`（红色，判错）→ `lastWrongAt` 更新为本次时间。
2. `correct === true && confidence === "guessed"`（黄色，猜对）。

**移出条件**：

1. 手动移出：`state → "removed"`、`removedReason="manual"`、`removedAt=now`、`confidentStreak=0`。
2. 自动移出：`state==="active"` 时，连续 2 次「有把握答对」（`correct && confidence==="confident"`）→ `state → "removed"`、`removedReason="auto2"`、`removedAt=now`、`confidentStreak` 归 0。
   - 连续中断规则：任何一次非「有把握答对」（判错、或猜对）都使 `confidentStreak` 归 0；猜对同时触发进入条件（保持 `active`）。

**重新进入**：已 `removed` 的题再次满足进入条件 → 重新 `active`，`addedAt` 更新，`confidentStreak=0`。

**状态机（冻结）**：

```
         判错 / 猜对
未在错题本 ──────────────► active
   ▲                         │
   │                         ├─ 连续2次「有把握答对」 ─► removed(auto2)
   │                         └─ 手动移出 ─────────────► removed(manual)
   │                                                       │
   └────────────── 再次判错 / 猜对（重新进入）◄────────────┘
```

- **哪些模式写错题本**：`practice_chapter`、`practice_random`、`wrongbook` 一定写；`mock` 默认**不自动写**（见 13.2 默认值）。
- 错题本条目与 `records` 相互独立：手动移出不会删除任何作答记录（统计仍包含该次作答）。

### 8.4 掌握指数（冻结，D7）

**单题**：

```
attempts          = 该题在本人的去重记录条数（含判错、猜对、有把握对；不含跳过）
confidentCorrect  = correct=true 且 confidence=confident 的次数
guessedCorrect    = correct=true 且 confidence=guessed 的次数
wrong             = correct=false 的次数（无信心的判定）
attempts === confidentCorrect + guessedCorrect + wrong        （恒等式，必须成立）

index = (confidentCorrect × 1 + guessedCorrect × 0.5 + wrong × 0) / attempts × 100
index = Math.round(index × 10) / 10        // 保留 1 位小数
insufficient = attempts < 3                 // 样本不足
```

- `attempts === 0` 时：`index = null`、`insufficient = true`。
- `insufficient === true` 时界面显示「样本不足」，**不显示数值**；导出中同时保留 `index` 数值（可为小数）与 `insufficient` 标记（见 9.9 返回值）。
- 取值范围 `[0, 100]`，仅由 `confidentCorrect` 与 `guessedCorrect` 贡献权重（1 与 0.5）。

**全局（个人总览）**：

```
totalAttempts = Σ attempts（去重记录总数）
index = (Σ confidentCorrect × 1 + Σ guessedCorrect × 0.5) / totalAttempts × 100
insufficient = totalAttempts < 3
```

- 全局掌握指数是**加权平均**（分子分母各自求和），不是各题指数的算术平均；不得用「各题 index 求平均」实现。

**分章/分题型掌握指数**：对该分组内的题目集合按上式聚合（`attempts` 为该分组内所有题的作答次数之和）。样本不足规则相同（组内总作答 < 3）。

### 8.5 个人统计（`CQP.personalStats`）

对某昵称的去重记录集合计算：

| 指标 | 定义 |
| --- | --- |
| `answered` | 去重记录条数 |

### 8.6 个人易错题与团队易错题（冻结，D9）

**个人易错题**（针对某昵称）：该昵称**判错过至少 1 次**的题目（`correct=false`，不含仅猜对的题）。

| 字段 | 定义 |
| --- | --- |
| `qid` | 题目 id |
| `wrongCount` | 该昵称判错次数 |
| `correctCount` | 该昵称答对次数（含有把握对与猜对） |
| `guessedCorrect` | 该昵称猜对次数 |
| `lastWrongAt` | 最近判错时间（ISO-8601） |
| `masteryIndex` / `insufficient` | 8.4 单题结果 |

排序：`wrongCount` 降序 → `guessedCorrect` 降序 → `lastWrongAt` 降序 → `qid` 升序。

**团队易错题**（跨全部昵称）：

| 字段 | 定义 |
| --- | --- |
| `qid` | 题目 id |
| `wrongUsers` | **判错过该题的不同昵称数**（同一人多次判错只算 1 人） |
| `wrongUserNames` | 上述昵称数组，按昵称升序 |
| `wrongCount` | 所有昵称判错该题的**总次数** |
| `answeredUsers` | 作答过该题（含答对）的不同昵称数 |
| `wrongRate` | `wrongUsers / answeredUsers × 100`，保留 1 位小数；`answeredUsers=0` 时 `null` |
| `teamMasteryIndex` / `insufficient` | 全体记录按 8.4 聚合的该题掌握指数 |

入选条件：`wrongUsers ≥ 2`（固定阈值 `CQP.WRONG_THRESHOLD_USERS = 2`）。
排序：`wrongUsers` 降序 → `wrongCount` 降序 → `qid` 升序。

**成员对比表**：每个昵称一行，列 = 昵称、作答数、正确数、正确率、掌握指数（样本不足时显示「样本不足」）、个人易错题数、模拟赛最高分。
**交叉矩阵**（可选展示）：行 = 团队易错题 qid，列 = 昵称，单元格 = `对 / 错 / 猜对 / 未做`（未做 = 无记录）。

### 8.7 本地自然日（冻结，D13）

- `localDateOf(tsISO)`：解析 ISO-8601（含偏移），按**该字符串自身的偏移**换算成当地日期，返回 `YYYY-MM-DD`。示例：`"2026-10-05T23:30:00+08:00"` → `"2026-10-05"`；`"2026-10-05T23:30:00+00:00"` → `"2026-10-05"`（按 +00:00 当地日期）。
- 「今天」= `localDateOf(nowISO)`，`nowISO` 由 `new Date()` 按本机时区格式化生成。
- 日期筛选一律比较字符串（`YYYY-MM-DD` 字典序即时间序），不做时区二次换算。
- 区间筛选为闭区间 `[from, to]`。

### 9.3 判分（冻结）

```js
CQP.foldWidth(s: string): string
// 全角→半角折叠（r2，项目维护者决定 R2-1）：逐字符映射
//   U+FF01–U+FF5E（全角 ! 到 ~）→ 同序 ASCII 0x21–0x7E（即 code - 0xFEE0）
//   U+3000（表意空格）→ U+0020（半角空格）
//   其余字符（含中日韩汉字、全角标点以外的符号）原样保留
// 传入非字符串抛 TypeError。
// "ＳＭ４" → "SM4"；"２５６" → "256"；"　" → " "（U+3000 → 空格）；"ＡＢＣ" → "ABC"

CQP.norm(s: string, opts?: { foldWidth?: boolean }): string
// = [foldWidth(s) 若启用] → trim → toLowerCase
// 启用规则（与实现一致）：opts.foldWidth === false → 本次不折叠；
//   否则取 CQP.DEFAULTS.blankFoldWidth（false → 不折叠；true/缺省 → 折叠）
// 传入非字符串抛 TypeError。
// 默认（blankFoldWidth=true）：
//   " SM4 " → "sm4"；"Sm4" → "sm4"；"SM 4" → "sm 4"（内部空格不处理）；
//   "ＳＭ４" → "sm4"；"２５６" → "256"；"　SM4　" → "sm4"（表意空格折叠后由 trim 去掉）
// 关闭（CQP.DEFAULTS.blankFoldWidth=false 或 opts.foldWidth=false）：
//   "ＳＭ４" → "ｓｍ４"（不折叠，判为与 "sm4" 不等）

CQP.judge(question: Question, response: string[], opts?: { foldWidth?: boolean }): {
  correct: boolean,
  normalizedAnswer: string[],
  normalizedResponse: string[],
  reason: "exact" | "set_equal" | "string_match" | "no_answer" | "invalid_response"
}
```

判定流程（严格按此实现）：

1. `question.answer.length === 0` → `{correct:false, reason:"no_answer"}`（防御分支；当前题库 0 例，见 13.1）。
2. `response` 不是数组或含非字符串元素 → `{correct:false, reason:"invalid_response"}`。
3. `responseMode === "blank"`：`normalizedResponse=["norm(response[0] ?? "", opts)"]`，`normalizedAnswer = answer.map(a => norm(a, opts))`，逐个比较，任一相等即 `correct:true, reason:"string_match"`（**两侧同时归一**，不允许只归一其中一侧）。
4. `responseMode === "judge"`：`response[0] === answer[0]`（严格 `"对"`/`"错"`）→ `exact`。
5. `responseMode === "single"`：`response.length===1 && response[0]===answer[0]` → `exact`。**注意**：`responseMode="single"` 但用户传入多元素 → 判错。
6. `responseMode === "multiple"`：先各自升序去重，再比较数组是否逐元素相等 → `set_equal`；长度不等直接判错。

边界样例（验证者按此表逐行断言，`T-09-01`～`T-09-08`、`T-09-15`、`T-09-16`）：

### 10.2 抽题分布规则（本平台默认，计算过程冻结）

采用**两级最大余数法**：先按题型占比分配 100 题，再在题型内按章占比分配，最后各章内随机抽题。

候选池（题型 × 章）实测规模（用于本计算，`answerStatus="ok"`；r2 起全部 1051 道均有答案）：

| 章 \ 题型 | single | multiple | judge | blank | 合计 |
| --- | --- | --- | --- | --- | --- |
| C01 | 40 | 13 | 12 | 0 | 65 |
| C02 | 30 | 10 | 10 | 0 | 50 |
| C03 | 35 | 10 | 10 | 0 | 55 |
| C04 | 25 | 10 | 10 | 0 | 45 |
| C05 | 156 | 130 | 80 | **30** | **396** |
| C06 | 115 | 60 | 20 | 0 | 195 |
| C07 | 90 | 125 | 30 | 0 | 245 |
| **合计** | **491** | **358** | **172** | **30** | **1051** |

第 1 级（题型配额，权重 = 题型池 ÷ 1051，余数相同按官方顺序 `blank → multiple → single → judge` 优先）：

| 题型 | 精确值 | 取整 | 余数 | 最终配额 |
| --- | --- | --- | --- | --- |
| blank | 100×30/1051 = 2.8544 | 2 | .8544 | **3**（余数最高） |
| multiple | 100×358/1051 = 34.0628 | 34 | .0628 | **34** |
| single | 100×491/1051 = 46.7174 | 46 | .7174 | **47**（余数次高，取到第 2 个待分配席位） |
| judge | 100×172/1051 = 16.3654 | 16 | .3654 | **16** |
| 合计 | — | 98 | — | **100** |

> r2 复核：即使填空池由 29 增至 30（总池 1050→1051），两级最大余数法的结果**完全不变**（剩余 2 个席位仍按余数次序给 `blank` 与 `single`，第 2 级各章池未变），故 10.2 的全部配额（题型 3/34/47/16、各章 6/5/5/4/37/19/24）保持 v1.0.0 的数值 —— 见 T-10-02。

第 2 级（题型内按章分配，余数相同时按 `C01…C07` 顺序优先）：

| 题型 | C01 | C02 | C03 | C04 | C05 | C06 | C07 | 合计 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| single | 4 | 3 | 3 | 2 | 15 | 11 | 9 | 47 |
| multiple | 1 | 1 | 1 | 1 | 12 | 6 | 12 | 34 |
| judge | 1 | 1 | 1 | 1 | 7 | 2 | 3 | 16 |
| blank | 0 | 0 | 0 | 0 | 3 | 0 | 0 | 3 |
| **按章合计** | **6** | **5** | **5** | **4** | **37** | **19** | **24** | **100** |

- 抽取顺序：题型 `blank` → `multiple` → `single` → `judge`；同一题型内章顺序 `C01…C07`；章内用 `CQP.makeRng(seed)` 洗牌取前 N。
- 试卷呈现顺序：**按题型分块，顺序为 填空 → 多选 → 单选 → 判断**，块内按章序、`seq` 升序；与官方「同分先比填空」的侧重一致（题目顺序官方未公布，见第 13 章）。
- 任一格配额超出该格池大小时，差额按「题型总配额不变」原则回流到同题型内池最大的章（确定性规则，当前数据不会触发）。

### 10.3 答题与计时

1. 进入模拟赛前显示确认页：题量 100、限时 60 分钟、满分 100、到点自动交卷、**不及格不扣分但记录成绩**；「开始答题」为唯一入口。
2. 交卷前**不显示对错、不显示正确答案、不显示信心选择**（避免泄露答案）。
3. 每题独立记录 `elapsedMs`（进入该题到离开/交卷的毫秒数）；切换题目时结算上一题用时。
4. 题号面板显示「已答 / 未答 / 已标记」，点击跳题；支持「标记待回看」（仅本地 UI 状态，不入库）。
5. 剩余时间 ≤ 0：立即停止作答、以当前已答内容交卷，`autoSubmitted=true`。

### 10.4 交卷与成绩（冻结顺序）

交卷后计算并展示：

```
总分 = 答对题数 × 1                       （满分 100）
总用时 = min(3600, 实际经过秒数) 秒
分项（固定顺序 填空 → 多选 → 单选 → 判断）：
  填空题：得分 / 题数 / 用时
  多选题：得分 / 题数 / 用时
  单选题：得分 / 题数 / 用时
  判断题：得分 / 题数 / 用时
rankKey = [总分, -总用时(毫秒), 填空得分, 多选得分, 单选得分, 判断得分]
```

- 每型「用时」= 该题型所有题的 `elapsedMs` 之和；未作答题按实际分配用时计入（0 或不含，规则：未作答题的用时不计入任何题型，但在 `totalElapsedMs` 中按实际经过时间计入）。
- 成绩页同时展示：本次抽题的章/题型分布（10.2 实际值）、错题清单（可一键加入错题本，见 13.2 默认值）。
- 交卷后**不允许修改答卷**；可「再来一次」生成新试卷（新 `sessionId`）。

### 10.5 排名键（冻结，供团队对比使用）

```
rankKey(result) = [score, -totalElapsedMs, blank.score, multiple.score, single.score, judge.score]
比较规则：按数组依次比较，数值大者靠前。
```

- 该键与官方「总答题用时较少者靠前 → 依次比较 填空 → 多选 → 单选 → 判断」一致（学生组还含个人成绩比较，本平台只做个人级对比与展示）。

| 是否做全角→半角折叠 | **做，默认开启**（r2 项目维护者决定 R2-1，0.3）：比较前对用户输入与标准答案**两侧同时**折叠 `U+FF01–U+FF5E → U+0021–U+007E`、`U+3000 → U+0020`，随后 `trim` + `toLowerCase`，再按多答案任一命中判定；开关 `CQP.DEFAULTS.blankFoldWidth`（默认 `true`）。**关闭后的行为**：退化为 v1.0.0 的 `trim + toLowerCase`，全角输入（`ＳＭ４`、`２５６`）判错。**影响面**：仅填空判分路径（`CQP.norm` / `CQP.judge` 的 `blank` 分支），不改题库数据、覆盖层、错题本、统计与导出结构；另支持 `CQP.norm(s, {foldWidth:false})` 单次关闭（测试与个别豁免用）；用户否决时只需把常量置 `false`（见 §16） |
| 是否删除内部空格 | **不删除**（`"SM 4"` ≠ `"SM4"`；`"Ｓ Ｍ４"` 折叠为 `"s m4"` 后同样判错） |
| 是否需要宽松匹配/同义替换（如 `"SM4算法"` 视为 `"SM4"`、`"128"` 视为 `"128.0"`） | **不做**；由用户在覆盖层为该题补多答案（D4 已确认支持多答案） |
| 数值题容差 | **不设**（`"128"` 与 `"128.0"` 不等价） |

## 14. 风险与缓解

| 风险 | 影响 | 缓解（必须实现或必须遵守） |
| --- | --- | --- |
| `file://` 下 `localStorage` 被浏览器策略限制（个别版本/策略） | 数据无法保存 | 启动自检：写入探测键并读取；失败 → 显示 11.2.5 提示 + 引导导出；T-12-03 覆盖 |
| `localStorage` 容量上限（约 5MB/域） | 写入失败丢数据 | 单条 ≈320 字节；写入失败给阻断式提示；首页常驻「导出备份」按钮；首页显示记录条数与近似占用 |
| 题库 PDF 解析缺陷（缺陷 A–G） | 题量/答案错位 | 构建脚本按 5.3.2 逐条处理并输出 `build-report.json`；`validateBank` 作为构建门禁（非 0 退出）；缺陷题在界面标注「待校对」 |
| 解析后题干粘行/断行不规范（PDF 换行） | 题干可读性 | 断行合并规则见 5.3 `stem`；构建报告输出被合并行数供抽查 |
| 导入他人文件含未知 id 或未来版本 | 统计污染 | 按 7.5/7.6：未知 id 不入库、版本不符拒收、坏记录跳过并报告 |
| 时区/跨日记录（23:59 作答、次日导出） | 按日筛选出错 | 记录固化 `localDate`，筛选只比字符串（8.7）；T-07-01 覆盖跨日边界 |
| 用户清空浏览器数据 | 学习记录丢失 | 首页常驻导出入口；导出后文件名带昵称与日期便于归档 |
| 多人昵称重复 | 团队统计串号 | 昵称作为身份的既定口径（G-6）；界面在团队对比表中显示各昵称记录数与 `deviceId` 前缀以便人工识别 |
| 单文件体积（1051 题 JSON + 逻辑） | 打开变慢 | 题库 JSON 为纯文本内嵌；首屏仅渲染必要 DOM，长列表虚拟滚动或分页（≥200 行时启用）；目标 < 300ms |
| 浏览器差异（Chrome/Edge/Firefox） | 行为不一致 | 只用 ES2020 标准 API；不用 `:has()` 等新 CSS；T-12-05 覆盖 |
